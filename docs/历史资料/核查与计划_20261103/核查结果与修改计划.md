## 2. 已确认的参数和实现

| 项目 | 源码／配置事实 |
|---|---|
| 实机模型默认值 | 两份 live launch 均指向 `models/yolov8n-seg.pt`；MobileNet 需另行指定 |
| 分割与同步 | 输入尺寸 640，置信度 0.35；RGB、Depth、CameraInfo 近似同步容差 0.04 s；每 3 帧处理 1 帧；推理等待队列容量 1 |
| 推理设备 | `Semantic-SLAM-deploy/config/live.yaml` 为 `cpu`；Jetson 副本为 `"0"`，CUDA 不可用时拒绝启动 |
| 投影 | 16UC1 毫米转米，32FC1 按米；保留 0.3—5 m，横纵各间隔 4 像素采样 |
| 相机约束 | RGB、深度同尺寸、同光学 frame；内参有效，代码要求畸变系数近零。仅话题名含 `aligned_depth` 不足以证明所有条件满足 |
| TF | 按深度采集时间查询，最多等待 5 s；不退回最新位姿。TF 等待队列容量 40，满时另计丢帧 |
| 地图 | 0.05 m 体素，上限 200000；每帧每体素每类最多一票；累计地图按 1 s 定时器检查更新，不能据此称整管线 1 FPS |
| 保存 | 每 10 s 保存；正常关闭再次保存 PLY、NPZ 和统计；另有 `/semantic/save_map` 服务 |
| 当前边界 | 无跨帧实例身份、动态点清理、回环后历史语义重投影；语义不参与定位、回环或后端优化 |

体素坐标由去重后的代表观测累计求均值，不是对所有投影像素直接求均值。累计地图的 `instance_id` 保存最近写入的观测编号，也不表示稳定物体身份。

依据：两份 `config/live.yaml`；`semantic/yolo_detector.py`、`semantic_projector.py`、`semantic_grid_node.py` 和 `common.py`。

## 3. 入口与接口差异

`run_live.sh → launch/live_semantic.launch.py` 仅启动分割、投影、语义累积和可选 RViz。它依赖外部 RGB-D 与几何位姿链，**不启动 RTAB-Map、相机或雷达驱动**。

`run.sh → scripts/run_demo.py → launch/indoor_semantic.launch.py` 是官方 Indoor 回放入口。其调用的 RTAB-Map 官方 launch 订阅激光，使用里程计 TF，并设置 ICP 配准；这不是旧实车手推配置。

旧 `run_handpush.sh → scripts/run_handpush.py` 会启动相机、雷达、RGB-D 视觉里程计和 RTAB-Map。几何 frame 使用 `camera_link/camera_odom`；雷达只录制，状态明确为 `lidar_used_for_mapping=false`。该入口还强制 Domain 77、仅本机通信，不能直接复用为下一轮整合系统的多传感器入口。

| 配置差异 | 部署整理版 | Jetson 历史副本／交接资料 |
|---|---|---|
| RGB 默认话题 | `/camera/color/image_raw` | `/camera/camera/color/image_raw`；交接稿另列 `/camera/color/image_rect_raw` 候选 |
| 深度与内参前缀 | `/camera/...` | `/camera/camera/...` |
| Domain / 本机通信 | live 不强制指定，沿用环境 | Jetson live 默认 77/1；手推入口强制 77/1；通信手册约定 0/0 |
| 运行环境 | 本地 `.venv`，可加载 RTAB-Map 工作空间 | `scripts/ros_env.sh` 指向 `envs/yolo/bin/python`；不可复制 x86 环境代替 ARM64 环境 |

下一轮需在本组启动端对齐话题、Domain、QoS 和命名空间；不覆写其他组的 shell 或 FastDDS 配置。若已有 2D 定位发布 `/map` 或 `map→odom`，先明确几何结果与 TF 的发布责任，避免启动第二个同名发布者。

核查中新增三点说明：

1. 回放稿中的“独立 TF 重算 206 次”对应 `events.json` 的验证快照；最终 `verification.json` 为 211 次。最大坐标分量差约 `9.54×10⁻⁷ m` 一致。后续选定统计时点，不能静默混用。
2. 手推 A 的 `recording.log` 在分卷和停止时多次显示 `Total lost: 12`；不能把重复打印直接相加，也不能写 A 全程零丢帧。B 停止时显示 19 条，与旧稿一致。下一轮应保存录制计数和丢消息统计的完整口径。
3. A、B 的 `verification.json` 虽为 `success=true`，只说明观察器的接口条件曾满足。A 的 `assessment.json` 明确 `route_mapping_success=false`；B 末尾 `tracking_valid=false`。接口通过不能替代路线建图验收。

A 的约 1.24 FPS 是整段采集的有效语义处理速率；Jetson 独立模型约 22.96 FPS 是另一项测试。两者不能混用。体素数、数据库节点数与最终位姿图规模也应分别报告。没有人工实例标注或参考轨迹，Mask mAP、mIoU、ATE/RPE 均写“未评估”。

主要证据目录：`Semantic-SLAM/runs/20261009-184520-4455/`、`live_robot_test_20261023/handpush-20261023-161242/`、`live_robot_test_20261023/handpush-20261023-162853/`。本轮是复核既有文件，没有重跑实验。
