## 4. 语义发布与接收契约

表内 Image、CameraInfo、PointCloud2 均属于 `sensor_msgs/msg`；String 属于 `std_msgs/msg`。所有名称都是当前源码中的绝对话题名，不会自动跟随外层命名空间改变。

| 话题 | 消息／内容 | 发布节点 → 接收方 |
|---|---|---|
| `/semantic/label_image` | Image，mono8；0 背景，1—80 为 COCO 类别加一 | yolo_detector → semantic_projector／下游 |
| `/semantic/instance_image` | Image，mono16；单次观测编号 | yolo_detector → semantic_projector／下游 |
| `/semantic/paired_depth` | Image，保留此次配对深度 | yolo_detector → semantic_projector |
| `/semantic/paired_camera_info` | CameraInfo，此次配对内参 | yolo_detector → semantic_projector |
| `/semantic/image_annotated` | Image，bgr8，预测叠加图 | yolo_detector → 显示／记录方 |
| `/semantic/points_camera` | PointCloud2，相机系有效语义点 | semantic_projector → semantic_grid_node |
| `/semantic/pointcloud` | PointCloud2，单帧地图系语义点 | semantic_grid_node → 显示／下游 |
| `/semantic/map` | PointCloud2，累计语义地图 | semantic_grid_node → 显示／下游 |
| `/semantic/detector_status` | String，JSON：处理帧、预测耗时、时间差、实例预测 | yolo_detector → 观察／诊断方 |
| `/semantic/map_status` | String，JSON：TF、队列、体素等计数 | semantic_grid_node → 观察／诊断方 |

普通输出使用 Reliable、Volatile、depth 5。累计 `/semantic/map` 使用 Reliable、Transient Local、depth 1，下游按此配置才能在后加入时接收保留的地图。原投影器通过 `message_filters.TimeSynchronizer(..., 20)` 精确配对类别图、实例图、深度和内参。

类别图、实例图、标注图和配对内参的 header 使用配对深度时间；相机系和当前地图系点云也保留该时间。标注图的像素仍来自 RGB，RGB 与 Depth 的差值写在 detector_status 中。累计地图 header 是发布时刻，不表示所有历史点在该时刻采集。

累计语义地图只包含检测目标中具有有效深度的点，不是完整房间的几何重建。墙面或地面没有类别颜色，不能单凭这一点判断几何建图失败。

三个点云接口的字段均为：`x/y/z/rgb` 为 FLOAT32，`class_id/instance_id` 为 UINT32，每点 24 字节。坐标单位米；`rgb` 是打包显示色，不能作为普通浮点强度解释。点云 `class_id` 为 0—79，与类别图的 1—80 编码不同。`instance_id` 会循环使用，不能当作跨帧稳定身份；累计体素里也是观测编号。

TF 查询以深度采集时刻为准，目标 frame 默认 `map`，可通过本组参数调整。5 s 后仍取不到 TF 会丢帧，不回退到最新位姿。TF 队列容量 40，队列丢弃与超时分别计数。无有效语义点时不发布非空点云，不能只凭没有点云认定分割程序崩溃。

累计地图每 1 s 检查一次更新，仅 dirty 时发布。该定时器频率、每 3 帧抽 1 帧和单次推理耗时均不能替代实测整管线 FPS。

几何接口 `/map`（OccupancyGrid）、`/mapData`（MapData）、`/mapGraph`（MapGraph）由另行启动的 RTAB-Map 提供；后两者属于 `rtabmap_msgs/msg`。本组语义 live 入口不创建它们。`/semantic/map` 是点云，不能直接当作 Nav2 的二维 OccupancyGrid 使用。

示例目前只在本地整理副本中，尚未上传到上述车上路径。`--kind` 还支持 cloud、label、instance、annotated、map_status；用 `--topic` 指定协商后的输出名。

源码中的发布方式可直接定位：`yolo_detector.py` 用 `create_publisher(Image, '/semantic/' + name, 5)` 创建图像输出；`semantic_projector.py` 发布 points_camera；`semantic_grid_node.py` 发布单帧点云和带 Transient Local QoS 的累计地图。订阅处理入口分别是 `YoloDetector.receive/process`、`SemanticProjector.project`、`SemanticGrid.receive/transform_pending`。点云线格式集中在 `semantic/common.py`。

```bash
ros2 service call /semantic/save_map std_srvs/srv/Trigger '{}'
```

该调用写出 `semantic_map.ply`、`semantic_map.npz` 和 `map_stats.json`，不保存 RTAB-Map 数据库，也不停止底盘。节点每 10 s 自动保存，正常退出再次保存。前台 live 用自己终端中的 Ctrl+C；`stop.sh` 仅管理回放，不能当作通用停车或其他组节点停止命令。
